# 技术图谱（要学什么 · 够用标准 · 什么时候学）

> **起点**：C 语言入门、CubeMX + HAL 能点灯、Keil 会下载。没独立做过项目。
> 本文回答三个问题：这个项目一共要学多少东西、每项学到什么程度算够、什么时候必须会。
> 不回答「怎么练」（→ [`05_学习路线.md`](05_学习路线.md)）、也不回答「做什么」（→ [`01_项目规划.md`](01_项目规划.md) 第 3 节）。

## 0. 一句话

**一共 52 项，但 C1–C2 只需要 19 项，其中 2 项已经在仓库里了（单元测试、git 流程）。**

所以不要按「先把技术学完再做项目」的顺序——那个顺序永远学不完。
正确的顺序是 **做到哪、学到哪**，判据只有一句：

> **这项技术对应哪个能演出来的功能？对应不上的，先不学。**

## 3. 现在就要（P0 · 19 项）——对应 C1–C2

### 3.1 嵌入式 C（5 项）

| 技术项 | 用在哪 | 够用标准（能做到就算过） |
|---|---|---|
| 指针与数组 | 缓冲区、`uint8_t *payload`、解析器入参 | 能手写 `memcpy` 的循环版，能说清 `a[i]` 与 `*(a+i)` 等价 |
| 结构体与结构体指针 | `frame_t`、`servo_t`、状态槽 | 能用 `->` 传结构体进出函数，知道为什么传指针不传值 |
| 位运算与寄存器 | 置位/清位、标志位打包、CRC | 能手写 `set/clear/toggle/test_bit`，能读懂 `GPIOA->ODR \|= (1<<5)` |
| `volatile` / `static` / `const` | 中断与主循环共享变量、模块私有状态 | 能说清 `volatile` 解决"编译器优化掉读"，**不解决**原子性 |
| 函数指针与表驱动 | 状态机转移表、命令派发表 | 能写"命令字符串 → 函数"的查找表，不用一长串 `if/else` |

> 这一层的判断标准不是"学过 C"，而是**能不能不借助 malloc 写出模块**。嵌入式里没有堆。

### 3.2 工具链与调试（5 项）

| 技术项 | 用在哪 | 够用标准 |
|---|---|---|
| CubeMX 勾 Makefile 工具链 | 让 CI 能编译固件（现在只有 Keil，CI 编不了） | 生成一次，`make` 能出 `.elf` |
| `arm-none-eabi-gcc` + `size` / `.map` | 内存预算、C5 端侧推理的前置能力 | 能读出 flash/RAM 各占多少、哪个函数最占空间 |
| Keil 断点 / 寄存器 / Call Stack | 定位"卡在哪一行" | 能靠断点+寄存器定位一个卡死，而不是靠 `printf` 猜 |
| 逻辑分析仪（协议解码） | PWM 对不对、I2C 有没有 ACK、UART 波特率 | 能抓出一次真实的时序错误并说清原因 |
| 万用表与供电排查 | 舵机一动就复位/花屏 | 能量电压、找虚焊、判断是不是供电塌了 |

> 这一层最容易被跳过，但它决定后面 200 小时是"调试"还是"瞎改"。

### 3.3 MCU 外设与底层（5 项）

| 技术项 | 用在哪 | 够用标准 |
|---|---|---|
| 时钟树与 RCC | 定时器频率、ADC 采样率、串口波特率全靠它 | 能手算 PSC/ARR 得到 50Hz PWM，并解释为什么 |
| GPIO 与复用 | 舵机信号、按键、片选 | 能说清推挽/开漏、上拉/下拉各用在哪 |
| TIM + PWM | 舵机、1kHz 节拍 | 舵机 0°/90°/180° 三点准，且知道角度-脉宽不是线性的 |
| I2C + SSD1306 | 表情脸 | 能写地址扫描器，能移植驱动并说清页寻址 |
| UART 中断收发 | 命令行、日志、与上位机 | 能实现不定长接收（IDLE+DMA）并处理半包/粘包 |

### 3.4 实时系统与架构（2 项）

| 技术项 | 用在哪 | 够用标准 |
|---|---|---|
| 中断优先级与职责划分 | 1kHz 电流环 vs 刷屏 | 能说清"中断里只置标志"，并解释为什么中断里不能刷 OLED |
| 非阻塞时间基准（`millis()`） | 眨眼、动画、超时 | 全项目不出现 `HAL_Delay` 也能跑出定时行为 |

## 4. 分水岭（P1 · 18 项）——对应 C3–C4

> C3 做完能去面实习；**C4 是分水岭**：有闭环叫工程经验，只有外设叫会调库。

### 4.1 控制与信号处理（9 项 · 全项目最硬的一块）

| 技术项 | 用在哪 | 够用标准 |
|---|---|---|
| 采样定理与抗混叠 | 1kHz 采电流，纹波在 10kHz 以上 | 能说清为什么采样前要 RC 低通，截止频率怎么定 |
| 数字滤波 | 去掉 PWM 与电刷噪声 | 能实现滑动平均/中值/一阶 IIR，并用波形对比效果 |
| 多点标定 | 脉宽→角度、ADC→电流 | 能做出标定表或拟合式，并给出残差 |
| 定点数学（Q 格式） | M3 无 FPU，浮点靠软件模拟 | 能用 Q12 做乘法并处理溢出，知道软浮点比整数慢多少 |
| 舵机模型 | 死区、回差、温漂、堵转电流 | 能量出一条"指令角 vs 实际角"曲线并解释偏差来源 |
| 电流 → 力矩估计 | 无传感器力觉的核心 | 能写出 `τ̂ = Kt·(i - i0)`，并说明摩擦与温度怎么补偿 |
| PID | 位置环 | 能整定出无超调或指定超调的响应，知道积分饱和怎么处理 |
| 导纳控制 | 被推让位、松手回弹 | 能实现 `Δθ = τ̂/K_virtual`，并测出跟随误差 |
| 堵转 / 过流保护 | 安全底线 | 能在 200ms 内识别堵转并卸力，误动作率可测 |

### 4.2 MCU 外设（2 项）

| 技术项 | 用在哪 | 够用标准 |
|---|---|---|
| ADC 采样参数 | 0.1Ω 采样电阻 → 几十 mV 信号 | 能算清采样时间、分辨率、Vref 对有效位数的影响 |
| DMA（循环模式 + 半传输） | 1kHz 连续采样不占 CPU | 能配出双缓冲，说清半传输中断为什么比全传输中断好 |

### 4.3 实时系统与架构（2 项）

| 技术项 | 用在哪 | 够用标准 |
|---|---|---|
| 环形缓冲（单生产者单消费者） | 中断写、主循环读 | 能写无锁版，并解释下标回绕为什么要用无符号减法 |
| 状态机（表驱动/层次） | 表情、行为、故障 | 能画出状态图并直接用表实现，加一个状态不改主流程 |

### 4.4 通信协议（2 项）

| 技术项 | 用在哪 | 够用标准 |
|---|---|---|
| 命令层与超时重传 | 串口命令、L1→L0 | 能设计"命令+序号+应答+超时重发"，不掉命令 |
| 心跳与版本兼容 | 断连降级、协议升级 | 能实现"3 次心跳丢失→进入独立模式"，并处理版本字段 |

### 4.5 上位机与数据分析（3 项）

| 技术项 | 用在哪 | 够用标准 |
|---|---|---|
| Python + pyserial | 采 4 类电流波形 | 能写脚本把串口数据存成 CSV，一次采 500 条 |
| numpy / matplotlib | 波形对比、阶跃响应、混淆矩阵 | 能画出"滤波前 vs 滤波后"和"P 太大时的振荡" |
| 数据可复现规范 | 简历上的每个数字 | 每条结论都有：原始 CSV + 脚本 + 一句结论（见 [`06`](06_仓库协作规范.md) §5） |

## 5. 系统级（P2 · 15 项）——对应 C5–C6

### 5.1 端侧 AI（8 项 · 目标岗位唯一完全空白的一块）

| 技术项 | 用在哪 | 够用标准 |
|---|---|---|
| 数据采集与标注 | 4 类力触（轻拍/重按/推/堵转） | 能采到每类 ≥120 条、标注可追溯 |
| 特征工程 | 时域（均值/峰值/过零率）+ 频域 | 能说清哪些特征对区分"轻拍 vs 重按"有用 |
| 决策树 / 随机森林基线 | 先有基线才有对比 | 能在 PC 上训出基线并导出准确率 |
| 1D-CNN | 直接吃原始波形 | 能训出小模型（参数量 <1k），准确率打平或超过基线 |
| int8 量化 | 20KB RAM 塞不下浮点模型 | 能说清 scale / zero-point，能手算一次 requantize |
| 推理引擎集成 | 跑在 F103 上 | 能用 TFLite Micro 或手写推理，单次 <1ms |
| 内存 arena 与预算 | 20KB RAM 的硬约束 | 能用 `.map` 证明峰值内存，能解释为什么要复用 arena |
| 评估方法 | 简历上写"准确率 XX%" | 会给混淆矩阵、交叉验证、消融对比（模型 vs 阈值 vs 决策树） |

### 5.2 实时系统（4 项）

| 技术项 | 用在哪 | 够用标准 |
|---|---|---|
| FreeRTOS（任务/队列/优先级） | 补 JD 关键词，且是真实需求 | 能拆出 ≥3 个任务并说明优先级依据 |
| 裸机 vs RTOS 对比 | 一个白捡的亮点 | 同一功能两版实现，给出抖动与最坏响应对比 |
| 看门狗与降级 | 无人值守时不能死 | 能设计"喂狗条件"，并演示卡死后自动恢复 |
| 故障注入 | "它坏的时候会怎样" | 6 类故障（心跳断、I2C NACK、ADC 饱和、UART 位翻转、主循环卡死、掉电）全过 |

### 5.3 通信协议（2 项）

| 技术项 | 用在哪 | 够用标准 |
|---|---|---|
| CAN（TJA1050 + 位时序 + 仲裁） | BMS 岗硬要求，机器人也用 | 能同一套帧协议做 UART/CAN 双实现并对比延迟 |
| 双板协议联调（STM32 ↔ ESP32-S3） | 异构架构 | 能定位"两边都以为自己对的"时序问题 |

### 5.4 工程化（1 项）

| 技术项 | 用在哪 | 够用标准 |
|---|---|---|
| tag / 发布 / benchmark 归档 | 交付作品集 | 每个能力级一个 tag，每个数字有出处 |

## 8. 依赖顺序（这些不能跳）

```
C 指针/结构体/位运算
      ↓
时钟树 → GPIO → TIM/PWM → 中断优先级 → 非阻塞时间基准
      ↓                                    ↓
I2C(OLED) ────────────────┐         环形缓冲 → 状态机
      ↓                   ↓                ↓
UART 收发 → 协议帧/CRC → 命令层 ────────→ 故障降级
      ↓
ADC 采样参数 → DMA → 滤波 → 标定 → 定点数学
                                  ↓
                          力矩估计 → PID → 导纳 → 堵转保护
                                  ↓
                        数据采集(Python) → 特征 → 模型 → 量化 → 端侧推理
                                  ↓
                            RTOS / CAN / 故障注入 / benchmark
```

**能并行的**：I2C 与 UART（都是"读手册+看波形"，可交替）；Python 分析与硬件并行（可以先处理已有 CSV）。
**不能并行的**：ADC 之前必须先有 1kHz 节拍；PID 之前必须先有标定；量化之前必须先有可用的浮点模型。

## 9. 自测十题（能答出来才算真的会）

1. 中断服务函数里为什么不能调用 `HAL_Delay()`？换个说法：为什么不能在中断里死等？
2. `volatile` 解决什么问题？**不解决**什么问题？（提示：`i++`）
3. 1kHz 环里插一次 8ms 的整屏 I2C 刷新会发生什么？怎么改？
4. 舵机堵转 700mA，0.1Ω 采样电阻上是多少 mV？放大 33 倍后 ADC 读到多少？（Vref=3.3V，12 位）
5. 为什么 int8 量化后要做 requantize？不做会怎样？
6. 环形缓冲的读写下标用 `uint16_t` 自然回绕，为什么"空/满"不能只靠比较下标？
7. `.map` 文件里 `.data` 和 `.bss` 的区别是什么？哪个占 flash？
8. 为什么用固定阈值判断"轻拍 vs 重按"一定会误触发？至少说两个原因。
9. CAN 相比 UART，在 BMS 和机器人里解决了什么 UART 解决不了的问题？
10. 单元测试能证明你的 CRC 实现是对的吗？为什么？（这题本项目里已经有实证答案）

> 第 10 题的答案在 [`../firmware/README.md`](../firmware/README.md) §4：回环测试只证明自洽。

## 10. 怎么用这份清单

1. **每完成一项，在 [`05_学习路线.md`](05_学习路线.md) 对应周次打勾**，并写一句"我用它做出了什么"。
