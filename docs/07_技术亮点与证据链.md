## 4. 新增亮点 A：端侧推理落地（优先级最高）

### 问题

项目定位是具身智能，但 L0 上没有任何模型。"端侧 AI"这个词现在只出现在文档标题里。

### 做法

在 **STM32F103C8T6（Cortex-M3 @72MHz，64KB Flash / 20KB SRAM，无 FPU、无 DSP 扩展）** 上，
把电流波形分类从"决策树"升级为 **int8 定点量化 1D-CNN**，并做三方对比：

```
方案        体积        单次推理     准确率    说明
──────────┼───────────┼───────────┼────────┼──────────────────────
手工特征+阈值   <0.5KB      <50μs      基线     无学习能力
决策树        ~1KB        <100μs     基线     P1 先跑这个
int8 1D-CNN   ~4KB        待实测      目标 ≥85% 本文新增
```

网络规模控制在 **5k 级 MACs**（如 Conv1D 1→8 k5 s2 → Conv1D 8→8 k3 s2 → FC → 4 类，约 264 参数），
输入为每 20ms 一个周期的 200 点（10kHz）双通道波形。

**真正的工程量不在训练，在这四件事**——它们才是面试要聊的：

| 难点 | 具体问题 | 你需要的答案 |
|---|---|---|
| 内存 | 20KB RAM 里有 1KB 帧缓冲 + 200 点双缓冲 + 协议栈 | 单一 arena 复用中间张量，不按层分配；算清峰值 |
| 算子 | M3 无 DSP 指令，int8 卷积靠查表 + SIMD-in-a-register | 用 CMSIS-NN，并说清它怎么用 `__SMLAD` 一次算两个 MAC |
| 重缩放 | 每层输出要 requantize（`(acc * M) >> shift`），M 是定点 | 说清为什么不能直接用 float 缩放系数 |
| 时序 | 推理必须让出 1kHz 环 | 分片推理：一个周期算一层，20ms 内摊完；或提到 50Hz |

### 跨平台对比（白捡的加分项）

P2 引入 ESP32-S3（Xtensa，带 DSP/向量扩展）后，**同一个模型跑两个平台**：

> M3 无 DSP vs S3 有 DSP，同一 int8 模型推理耗时差多少？值不值得为省 1ms 换芯片？

这是真实的端侧 AI 选型问题，而且数据你已经有了（两块板都在手上）。

### 验证

- [ ] 三方案在同一测试集（≥500 样本，含 4 类）上的准确率 / 混淆矩阵
- [ ] Flash 与 RAM 实测占用（`.map` 文件截图，不靠估算）
- [ ] 单次推理周期数（DWT 打点，换算 μs）
- [ ] 峰值 RAM 与 1kHz 环的最坏执行时间（WCET 粗测）
- [ ] 跨平台对比表（P2）

### 为什么不是噱头

"我在 MCU 上跑了神经网络"谁都能说。**能说出"为了塞进 20KB 我把中间张量复用到 3.1KB、把 float 缩放换成定点移位、把推理切成 5 片塞进 20ms 周期"的人不多。**
这一段是整份简历里最难被追问倒的部分，也最容易被追问——所以要真做。

### 面试会问

1. 20KB RAM 怎么放下的？峰值多少？怎么算的？
2. 量化后精度掉多少？怎么补救的（per-channel 还是 per-tensor）？
3. 为什么不用 float？F103 上 float 推理慢多少倍？
4. 推理占了 1kHz 环多少时间？怎么保证不超时？
5. 为什么最后选 CNN 不选决策树？——**如果没有明确结论，这一段就白做了**

## 5. 升级亮点 B：从"力分类"到"力闭环"

### 问题

现有 P1 只做到"识别 4 类状态 + 堵转卸力"。这是**感知**，不是**控制**。
机器人岗最想看你有没有闭环过。

### 做法（三层递进，做不完就停在任意一层，每层都能单独写简历）

**B1 · 在线基线自校准（必做，P1 内）**

SG90 的空载电流随角度、电压、温升漂移。固定阈值必然误触发。

- 滑动窗口中位数估计基线 `I0`，只在"判定为自由运动"时更新
- 迟滞带（hysteresis）避免在阈值附近抖动
- 记录 30 分钟连续运行的基线漂移曲线（**一张图就能说明你懂真实硬件**）

**B2 · 导纳控制雏形（P1 末，最有价值）**

```
τ̂ = Kt · (I − I0)                 # 无传感器力矩估计
Δθ = τ̂ / K_virtual                # 虚拟刚度：被推时让位
θ_cmd = θ_nominal + Δθ,  带虚拟阻尼与死区
```

被手指推动时舵机主动让位、松手回弹到原位。这就是协作机器人 **admittance control** 的极简版。

**必须回答的稳定性问题**（面试官一定问）：虚拟刚度取小为什么不会振？
答：靠虚拟阻尼 + 一阶低通 + 采样率（1kHz 对 50Hz 舵机带宽有 20 倍余量）+ 死区。

**B3 · 舵机健康监测（PHM，选做，成本极低）**

长期记录"自由运动段的电流基线"，基线随齿轮磨损/积灰缓慢上升 →
两周加速老化实验（连续运转）得到一条趋势曲线 → 超过阈值提示"该保养"。

这是**工业设备的思路**用在 5 块钱舵机上，反差感很强，而且只需要放着让它转。

### 验证

- [ ] 基线漂移曲线（30 分钟）
- [ ] 力估计误差（用砝码/弹簧秤做标定对照）
- [ ] 让位跟随误差、回位重复精度
- [ ] 误触发率（正常表情动作时的假阳性）
- [ ] 老化趋势曲线（选做）

### 面试会问

1. 怎么区分"被人推"和"负载变化 / 电压跌落"？
2. 舵机没有编码器，你怎么知道它真到位了？
3. 虚拟刚度、阻尼怎么整定的？振荡了怎么办？
4. 采样在 PWM 周期内哪个时刻？为什么？
5. 两路舵机互相干扰怎么办？

## 6. 升级亮点 C：可复现的实时性 + 故障注入

### 问题

"≤50ms" 现在是一个愿望。没有测量方法、没有数据、没有失败场景。

### 做法

**C1 · 时间契约 benchmark**

- DWT 周期计数器打点，明确"延迟"从哪一毫秒算到哪一毫秒（**这点必须写进文档，否则数据没意义**）
- 每项 ≥100 次采样，输出 **均值 / P50 / P95 / P99 / 抖动**
- 原始数据存 CSV + 分析脚本，任何人 clone 下来能复现同一张图

**C2 · 故障注入矩阵（具身智能岗的加分重灾区）**

| 故障 | 注入方式 | 期望行为 | 验收 |
|---|---|---|---|
| 心跳中断 | 拔 UART | 300ms 内卸力、进独立模式 | 不失控 |
| I2C 从机 NACK | 拔 OLED 线 | 不卡死，表情降级为"仅舵机" | 主循环不停 |
| ADC 饱和 | 强制堵转 | 200ms 内卸力报警 | 不烧舵机 |
| UART 位翻转 | 人为改字节 | CRC8 检出并丢弃 | 不误动作 |
| 主循环卡死 | 人为死循环 | 看门狗复位并记录原因 | 能自恢复 |
| 掉电重启 | 拔电源 | 状态从 Flash 恢复 | 不丢配置 |

每一条写成一个可重跑的测试用例，**"它坏的时候会怎样"比"它好的时候多好"更能证明工程能力。**

### 为什么对具身智能岗特别值

真机上跑的东西，面试官最怕"只在理想条件跑通过"。有故障矩阵的人，默认被认为上过真机。
