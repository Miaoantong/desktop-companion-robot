## 1. 定位

> **一个带力觉反馈的桌面机器人平台**：双自由度、1kHz 实时环、用舵机电流反推外力、STM32 上跑端侧推理、断连仍存活。
> 应用示例：学习场景下的在场感知与主动干预（场景定义见 §2.1）。

由此推出三条判断标准，后续所有取舍都按它们走：

1. **能力可迁移 > 场景好讲**：同一套代码要能同时对应机器人运动控制与储能电子两类系统的技术要求（见 §1.2）。
2. **评测标准是可测量**：每个功能必须有指标、有数据、能复现，否则不算做完。
3. **价值主张是稳定运行**，不是"看起来聪明"。

### 1.1 为什么选择"实时系统 + 力觉交互"这条主线

生成式工具已经能写出 SSD1306 驱动、配好 HAL、甚至完成原理图与 layout。
**写第一版实现正在贬值，确认它在真实条件下成立正在升值。**

分界线不在"软件 vs 硬件"，而在：

| 在贬值 | 在升值 |
|---|---|
| 在 IDE 里生成代码 | 在物理世界里定位问题 |
| 写第一版实现 | 测出它在什么条件下失效 |
| 拼一个能跑的 Demo | 让它连续跑 6 小时不掉帧、不烧舵机 |

因此本项目的重点不是代码行数，而是**每一处都留下可复现的测量**：
DWT 打点的延迟分布、示波器抓的电流波形、`.map` 文件里的真实内存占用、6 类故障注入的恢复时间。

这些数据的共同点是**依赖物理设备与现场判断**，无法由文本生成。调试的主要工具同样是软件（读寄存器、抓 log、写上位机、写测试），要避开的是"只会生成代码"，而不是"写代码"。

### 1.2 能力的可迁移性

同一批代码，两种行业语境。这不是准备两套说法，而是同一批代码从两个行业视角描述，**指标与细节必须完全一致**。

| 能力 | 机器人 / 具身智能 | 储能 BMS / 汽车电子 |
|---|---|---|
| 电流采样 | 无传感器力矩估计、触觉分级 | 高边 / 低边电流检测、过流保护 |
| 实时控制环 | 1kHz 舵机环、阻抗控制雏形 | 保护动作时间、任务调度实时性、WCET |
| 通信协议 | 上下位机协议、心跳与降级 | 类 CAN / Modbus 的帧结构、异常处理 |
| 端侧推理 | 端侧感知、边缘智能 | 边缘诊断（SOH 趋势、异常检测） |
| 故障与安全 | 故障注入、断连存活 | 多级故障保护、看门狗、失效安全 |

## 2. 功能边界

### 2.1 四个使用场景（功能清单的唯一来源）

> 不从"要用哪个外设"出发，从"用户看到什么"出发。
> **任何落不到场景里的功能都不做**，即使技术上更复杂。

| # | 场景 | 用户看到的现象 | 需要的能力 |
|---|---|---|---|
| **S1** | 用户坐下 | 转头朝向、睁眼（目标 <150ms） | 在场检测、转头、表情 |
| **S2** | 连续学习 25 分钟无动作 | 望一眼别处，或只做一个微表情，**不发声** | 时长统计、四级干预 |
| **S3** | 触摸头部 | 轻拍 = 眯眼；重按 = 皱眉并后撤；推动 = 让位后回弹 | 力估计、力度分级、导纳让位 |
| **S4** | 用户离开 / 返回 | 离开时闭眼；返回时缓慢睁眼，**不做瞬时切换** | 在场状态、状态平滑过渡 |

四个场景即全部产品范围，演示视频只覆盖这四件事。

### 2.2 六个功能闭环

每个闭环必须"有输入、有输出、可测量"，否则不立项。

| 编号 | 闭环 | 输入 | 输出 | 所在层 | 阶段 |
|---|---|---|---|---|---|
| **F1** | 在场感知 | 雷达、声学 | 在座 / 离开 / 时长 | L1 | P2 |
| **F2** | 表达 | 状态槽 4 维 | 表情 + 转头 + 灯 | L0 | P0 |
| **F3** | 触觉 | 舵机电流 | 力度分级 / 让位 / 卸力 | L0 | P1 |
| **F4** | 主动干预 | 时长、分心、时段 | 四级强度之一 | L2 → L0 | P3 |
| **F5** | 记忆 | 交互事件 | 跨会话回忆候选 | L2 | P3 |
| **F6** | 安全与降级 | 心跳、故障 | 卸力 / 独立模式 / 复位 | L0 | P1–P2 |

> F2、F3、F6 全部在 L0，**P1 结束时机器人已经"完整"了**；F1/F4/F5 是加在完整产品上的能力。
> 这个顺序不能反——先让它活着，再让它聪明。

### 2.3 v1.0 要做

- **在场感知**：雷达 + 声学判断在场状态与停留时长，默认不采集图像
- **专注干预**：四级强度（沉默 / 微表情 / 动作+表情 / 语音）
- **触觉交互**：用舵机电流反推外力，做摸头力度分级与柔顺退让
- **表达一致性**：表情、转头、语调由同一个"状态槽"派生
- **完全离线可运行**：断网、断连时降级但不崩

### 2.4 v1.0 不做

| 不做 | 原因 |
|---|---|
| 通用对话（见下方"预留"） | 打不过大厂，且会稀释技术主线 |
| 情绪识别（判断用户情绪状态） | 学术上不可靠，真实场景准确率低，无法复现 |
| 手机 App | 不服务于核心闭环 |
| 内置电池 | 续航会把项目拖死 |
| 堆砌传感器 | 每个都必须有闭环，否则不装 |

### 2.5 预留：对话模块（P4 可选）

定义为 L2 侧一个**可插拔的 dialogue provider**：

- 默认关闭，**不参与核心闭环**
- 接口只产出"话术文本"，**是否开口仍由主动策略决定**
- 目的是证明扩展性，不是做一个聊天机器人

> **判定标准：去掉它，项目依然完整；加上它，只多一个加分项。**

## 3. 能力阶梯与验收

按**依赖关系**推进，不绑日历。每一级都能独立演示、独立交付，中途停下不会留下半成品。

### 3.1 六级的阶梯

| 级 | 能力 | 最小可演示 | 关键指标 | 追踪 |
|---|---|---|---|---|
| **C1** | 会点灯说话 | 舵机转到指定角 + 串口命令行 | 角度误差 ≤2° | [#1](https://github.com/Miaoantong/desktop-companion-robot/issues/1) |
| **C2** | 会画脸 | 眨眼 + 表情切换 | ≥35fps | [#1](https://github.com/Miaoantong/desktop-companion-robot/issues/1) |
| **C3** | 会测电流 | 4 类波形可复现 + 分类 | 准确率 ≥85% | [#2](https://github.com/Miaoantong/desktop-companion-robot/issues/2) |
| **C4** | 会闭环 ★分水岭 | 轻拍 / 重按 / 推动 / 堵转 四种反应 | 卸力 ≤200ms，让位误差 ≤5° | [#2](https://github.com/Miaoantong/desktop-companion-robot/issues/2) |
| **C5** | 会想事 | 断连仍能自主表情 + 推理耗时 | 单次推理 ≤2ms，峰值 RAM ≤20KB | [#2](https://github.com/Miaoantong/desktop-companion-robot/issues/2)–[#3](https://github.com/Miaoantong/desktop-companion-robot/issues/3) |
| **C6** | 会做系统 | 6 类故障注入全过 + benchmark 表 | 每类恢复 ≤300ms | [#3](https://github.com/Miaoantong/desktop-companion-robot/issues/3) |

依赖关系——不是时间顺序，是**前一级出不来后一级就卡住**的关系：

```
C1 ──→ C2 ──→ C3 ──→ C4 ──→ C5
                └──────────→ C6
```

> **C4 是分水岭**：C1–C3 只涉及外设使用与开环输出，从 C4 起才有闭环控制与失效处理。

P3（认知层）与 P4（作品集）**不在这条阶梯上**——它们是加在完整产品之上的能力，砍掉不影响演示。

### 3.2 分级验收清单

以下清单同时是 Issue #1–#5 正文的单一来源（[`.github/ISSUES/`](../.github/ISSUES/)），改动时两处同步。

#### P0 · 脸 + 脖子 + 可测量（C1–C2）

按外设学习顺序推进，学一个外设加一个功能：

| 序号 | 学习内容 | 机器人功能 |
|---|---|---|
| 1 | GPIO 输出 | 点灯、状态指示 |
| 2 | GPIO 输入 + 外部中断 | 按键有反应 |
| 3 | 串口 UART | 打印状态、调试 |
| 4 | 定时器 + PWM | 控制舵机角度 |
| 5 | I2C | 驱动 OLED 显示 |
| 6 | 参数化表情 + 双舵机 | 表情脸 + 转头联动 |

**验收**：
- [ ] 表情脸：OLED 眨眼 / 开心 / 睡觉三种状态
- [ ] 转头：双舵机云台，转头到位 ≤ 150ms
- [ ] 表情改为**参数化渲染**（6~8 个连续参数，非贴图切换）
- [ ] 延迟测量框架：UART 打时间戳，能输出"触摸 → 表情"毫秒数
- [ ] README 里有第一份延迟数据

#### P1 · 电流感知触觉 ★ 第一个真创新点（C3–C4）

**验收**：
- [ ] 双通道电流采样：10kHz，TIM 触发 ADC + DMA 循环
- [ ] 四种波形可复现并截图：空载 / 轻触 / 推动 / 堵转
- [ ] 决策树分类器，4 类准确率 ≥ 85%（自采 500 样本）
- [ ] 摸头力度分级可用
- [ ] 堵转保护：检测到卡死 ≤ 200ms 自动卸力
- [ ] 60 秒 demo 视频

#### P2 · 异构架构 + 隐私在场感知（C5–C6）

**验收**：
- [ ] UART 协议跑通：定长帧 + CRC8 + 优先级 + 心跳
- [ ] 心跳超时 300ms → 舵机卸力、表情进入独立模式
- [ ] 跨板时钟同步（往返时延估计），能测端到端延迟
- [ ] ESP32-S3 端侧唤醒词跑通
- [ ] LD2410 在场检测，误报率 ≤ 10%

#### P3 · 认知层（产品之外，可选）

**验收**：
- [ ] 行为标签：在座 / 离开 / 看手机 / 低头 / 趴桌（不做情绪判断）
- [ ] 主动干预四级 + 打扰成本在线调整
- [ ] 记忆系统：遗忘曲线，跨会话回忆
- [ ] 干预接受率对比固定规则基线有提升

#### P4 · 完整作品（作品集收口）

**验收**：
- [ ] 外壳 + 完整整机
- [ ] benchmark 文档 + 消融实验
- [ ] 开源仓库（接线图、BOM、视频、README）
- [ ] 对话模块（可选）

## 5. 范围失控时的砍功能顺序

从先砍到后砍：

1. 对话模块（本来就是可选）
2. 人格漂移（保留纯记忆）
3. 主动策略的在线学习 → 退回固定规则 + 手动调参
4. 摄像头 → 只保留雷达（反而更符合隐私定位）
5. 总线舵机对比实验
6. 外壳（用亚克力 / 纸板）

**不可删的三项**——它们共同构成项目的技术叙事，删掉任何一项都会失去差异化：

> **电流触觉 + 隐私在场感知 + 慢脑快反射**
