# 学习路线（外设清单 · 不绑日历）

> 本文是**外设学习顺序与每阶段验收题**，不是项目计划。
> 项目推进以 [`01_项目规划.md`](01_项目规划.md) 第 3 节的能力阶梯（C1–C6）为准；
> 周次为相对编号，只表示先后，不对应具体日期。
> **要查"整个项目共需哪些技术、每项达标标准"，见 [`08_技术图谱.md`](08_技术图谱.md)**（52 项，按档分层）。
>
> **终点**：走完 A–E 五个阶段，对应能力阶梯的 **C1–C4**（表情脸 + 转头 + 串口命令 + 电流闭环）。

## 0. 怎么用

### 0.1 四条纪律

| 纪律 | 含义 |
|---|---|
| **一次只加一个变量** | 换外设时其他全部不变。同时改两处，出错无法定位 |
| **脱离参考实现重写一遍** | 能跑不算掌握，能独立重写才算 |
| **每阶段必须能演示** | 拿不出 30 秒演示，视为未完成 |
| **AI 生成的代码必须能逐行解释** | 解释不了就查手册。这条最容易被跳过，也最影响长期能力 |

### 0.2 三档强度

| 档位 | 节奏 | 单次时长 | 适用 |
|---|---|---|---|
| **低强度** | 每周 2 次 | 约 1 小时 | 考试周、期末 |
| **正常** | 每周 6 次 | 约 1.5 小时 | 常规学期 |
| **冲刺** | 每周 7 次 | 2~3 小时 | 寒暑假 |

**低强度期只做可中断的任务**：读手册、整理笔记、读他人的代码、复盘。
**不做**：需要连续两小时调试的、需要焊接的、需要采购元件的。

> 低强度的目的是维持手感，不是推进进度。手感中断后恢复成本远高于放慢节奏。

### 0.3 每个阶段的两项必做

**① AI 对照练习**
用 AI 生成该阶段的参考实现，逐行批注，找出至少 3 处：
- 写法正确但自身尚未理解的地方
- 写错或遗漏边界条件的地方

**② 仪器验证**
必须用逻辑分析仪 / 示波器 / 万用表验证一次，不能只依赖串口打印。

> 这一条是 AI 时代的分界：代码变便宜了，"能验证它对不对"变贵了。

### 0.4 本阶段明确不碰

FreeRTOS · ESP32 · 机器学习 · Linux · ROS2 · 任何 AI 框架

## 2. 阶段 A（第 1–2 周）：工具与地基

> 目标不是学外设，是**学会看程序在干什么**。

### 第 1 周 · 调试器

- [ ] Keil + ST-Link 能稳定下载程序
- [ ] 在 `while(1)` 里打断点，单步执行
- [ ] 观察 `GPIOA->ODR` 寄存器的值随单步变化
- [ ] 用 Call Stack 查看函数调用链
- [ ] 故意写个死循环，用暂停键定位卡在哪
- [ ] 读 RM0008 的 GPIO 章节
- [ ] 写一句笔记：点灯时，寄存器层面到底发生了什么

### 第 2 周 · C 语言补强

- [ ] 指针：写 `swap(int*, int*)`
- [ ] 指针与数组：用指针遍历数组
- [ ] 结构体：定义 `Motor { angle, min, max, speed }`
- [ ] 结构体指针：用 `->` 访问成员
- [ ] `volatile`：说清为什么中断里改的变量要加
- [ ] 位运算：`set_bit` / `clear_bit` / `toggle_bit` / `test_bit`
- [ ] 函数指针：写一个回调表

### 阶段 A 的 AI 对照练习

用 AI 生成一份"STM32 点灯 + 逐行解释配置"，逐行批注：

- 找出 **3 处写法正确但未真正理解**的地方（例如该引脚为何配置为推挽）
- 找出 **1 处它写错或过时**的地方（HAL 版本差异、时钟没使能等）
- 与手册结论冲突时，**以手册为准**

### 阶段 A 的仪器验证

- [ ] 万用表量 LED 两端电压，验证"高电平点亮"这个结论
- [ ] 用调试器读 `ODR` 实测值，和代码里写的对照

**阶段 A 验收题**

1. 程序卡死在 `HAL_Delay`，如何定位？
2. 中断里修改的全局变量不加 `volatile` 会怎样？
3. `GPIOA->ODR` 的 bit5 置 1，对应哪个引脚？

## 3. 阶段 B（第 3–5 周）：让时间可控

### 第 3 周 · 定时器与中断

- [ ] TIM 配 1ms 中断，用它闪灯
- [ ] **手算一遍** PSC / ARR 与计数频率的关系
- [ ] 写非阻塞 `millis()`
- [ ] 用 `millis()` 实现"每 500ms 翻转 LED"，程序里不出现 `HAL_Delay`
- [ ] 中断里只置标志位，处理放主循环

### 第 4 周 · PWM 与舵机

- [ ] 配 TIM PWM 50Hz（PSC=71，ARR=19999）
- [ ] 用 CCR 控制脉宽 500~2500μs
- [ ] 舵机转到 0°/45°/90°/135°/180°，用量角器验证
- [ ] 记录实际角度与 CCR 的对应表（**该对应关系并非线性**）
- [ ] 按键切换角度

### 第 5 周 · 加减速与标定

- [ ] 实现"平滑移动"（每 10ms 走 1°）
- [ ] 加梯形或 S 曲线加减速
- [ ] 做脉宽-角度标定表存进代码
- [ ] 软件限位（防止撞死）
- [ ] 串口打印当前角度

### 阶段 B 的 AI 对照练习

用 AI 给出 PSC/ARR 计算过程与一段 PWM 初始化代码：

- 自己手算一遍再对比——**不一致时必须能说清谁对**
- 检查它有没有考虑：定时器时钟来源、重装载预装载、舵机死区

### 阶段 B 的仪器验证

- [ ] 逻辑分析仪抓 PWM：确认周期 20ms、高电平宽度对应 CCR
- [ ] 示波器看舵机信号线上的实际脉宽

**阶段 B 验收题**

1. 为什么 PSC=71、ARR=19999 就是 50Hz？
2. 舵机抖动，可能有哪些原因？（至少 3 个）
3. 非阻塞延时是怎么实现的？

### 第 6 周 · I2C 与 OLED

- [ ] 写 I2C 地址扫描器，扫出 OLED 地址

- [ ] 读懂初始化序列里至少 5 条命令

### 第 7 周 · 图形与帧缓冲

- [ ] 建 1024 字节帧缓冲
- [ ] 画点、画线、画圆
- [ ] 对比整屏刷新与局部刷新的耗时

### 第 8 周 · UART 中断收发

- [ ] 串口中断接收单字节

- [ ] `printf` 重定向
- [ ] 命令解析：`angle 90` → 舵机转动

### 第 9 周 · 状态机

- [ ] 画状态机图
- [ ] 用 `switch-case` 或函数指针表实现
- [ ] 按键和串口命令都能触发切换
- [ ] OLED 显示当前状态

### 阶段 C 的 AI 对照练习

用 AI 生成一份"UART 不定长接收（IDLE + DMA）"，逐项追问：

- 半包怎么处理？粘包怎么处理？缓冲区溢出怎么办？
- DMA 循环模式和普通模式在这有什么区别？
- **找出它至少 2 处没考虑的边界情况**

### 阶段 C 的仪器验证

- [ ] 逻辑分析仪解码 I2C：看到从机地址、ACK、数据字节

**阶段 C 验收题**

1. I2C 为什么需要上拉电阻？取多大？
2. OLED 全屏刷新为什么慢？怎么优化？
3. 不定长串口数据如何判定一帧结束？

### 阶段 D 的 AI 对照练习

## 9. 四类常见停滞

1. **教程循环**：看视频 → 抄代码 → 能跑 → 误认为已掌握。  
   **对策**：脱离教程从零重写一遍。

2. **不会调试**：没有示波器、不会断点、只会 `printf` 和重启。  
   **对策**：阶段 A 内用熟调试器，可省下后续大量排查时间。

3. **贪多**：同时开 5 个外设，最后不知道错在哪。  
   **对策**：一次只加一个变量。

4. **AI 依赖**：直接采用生成结果，能跑即视为通过。  
   **对策**：每条生成代码须能逐行解释；每阶段至少一次仪器验证。  
   **代价**：后果不是变慢，而是出现问题时无法定位。

## 10. 卡住时的自查顺序

1. 电源对不对？（万用表量电压）
2. 地共了吗？
3. 引脚复用配了吗？（CubeMX 里看）
4. 时钟使能了吗？
5. 用逻辑分析仪看波形，不靠猜测
6. 最后才怀疑代码逻辑
7. 以上均排除后，把完整现象与已排除项整理成文字再求助——**描述现象的能力本身决定排查效率**
