> **起点**：STM32 只学过 CubeMX + Keil HAL 库入门，没有独立完成过项目
> **投入**：常规 10~20 小时/周；考试期可降到 2~3 小时/周
> **终点**：2027 年 4 月初交出「表情脸 + 转头 + 串口命令 + 第一个闭环」
>
> v2 变更：每个阶段新增 **AI 对照练习** 与 **仪器验证**；新增低强度模式与新的时间表。
> 原版按"每周稳定 10~20 小时"排，未考虑考试周，已作废。

## 0. 怎么用

### 0.1 四条纪律

| 纪律 | 含义 |
|---|---|
| **一次只加一个变量** | 换外设时其他全部不变。同时动两处，出错永远找不到原因 |
| **关掉教程重写一遍** | 能跑不算会，能脱离教程重写才算 |
| **每阶段必须能演示** | 拿不出 30 秒演示，就当没做完 |
| **AI 写的每一行，你都要能解释** | 解释不了就去查手册。这条最容易被跳过，也最值钱 |

### 0.2 三档强度

| 档位 | 节奏 | 单次时长 | 适用 |
|---|---|---|---|
| **低强度** | 每周 2 次 | 约 1 小时 | 考试周、期末、生病 |
| **正常** | 每周 6 次 | 约 1.5 小时 | 常规学期 |
| **冲刺** | 每周 7 次 | 2~3 小时 | 寒暑假 |

**低强度期只做"不打断就能完成"的任务**：读手册、整理笔记、读别人的代码、复盘、看视频。
**不做**：需要连续两小时调试的、需要焊板子的、需要买元件的。

> 低强度的目的是**保持手感**，不是推进进度。手感断了要两周才找回来，这比慢一点贵得多。

### 0.3 每个阶段的两项必做

**① AI 对照练习**
让 AI 写一份该阶段的实现，你逐行批注，找出至少 3 处：
- 它写得对，但你没看懂的地方
- 它写错或漏掉边界的地方

**② 仪器验证**
必须用逻辑分析仪 / 示波器 / 万用表验证一次，不能只靠串口打印和"看起来对了"。

> 这两条是 AI 时代的分水岭：代码变便宜了，"能验证它对不对"变贵了。

### 0.4 这个阶段明确不碰

FreeRTOS · ESP32 · 机器学习 · Linux · ROS2 · 任何 AI 框架

## 2. 阶段 A（W1–W2）：工具与地基

> 目标不是学外设，是**学会看程序在干什么**。

### 第 1 周 · 调试器（已完成；若未做，在考试期补）

- [ ] Keil + ST-Link 能稳定下载程序
- [ ] 在 `while(1)` 里打断点，单步执行
- [ ] 观察 `GPIOA->ODR` 寄存器的值随单步变化
- [ ] 用 Call Stack 查看函数调用链
- [ ] 故意写个死循环，用暂停键定位卡在哪
- [ ] 读 RM0008 的 GPIO 章节
- [ ] 写一句笔记：点灯时，寄存器层面到底发生了什么

### 第 2 周 · C 语言补强

- [ ] 指针：写 `swap(int*, int*)`
- [ ] 指针与数组：用指针遍历数组
- [ ] 结构体：定义 `Motor { angle, min, max, speed }`
- [ ] 结构体指针：用 `->` 访问成员
- [ ] `volatile`：说清为什么中断里改的变量要加
- [ ] 位运算：`set_bit` / `clear_bit` / `toggle_bit` / `test_bit`
- [ ] 函数指针：写一个回调表

### 阶段 A 的 AI 对照练习

让 AI 写一份"STM32 点灯 + 逐行解释配置"，然后：

- 找出 **3 处它说得对、但你没真懂**的地方（比如为什么这个引脚要配成推挽）
- 找出 **1 处它写错或过时**的地方（HAL 版本差异、时钟没使能等）
- 它的说法和你读手册的结论不一致时，**以手册为准**

### 阶段 A 的仪器验证

- [ ] 万用表量 LED 两端电压，验证"高电平点亮"这个结论
- [ ] 用调试器读 `ODR` 实测值，和代码里写的对照

**阶段 A 验收题**

1. 程序卡死在 `HAL_Delay`，你怎么定位？
2. 中断里修改的全局变量不加 `volatile` 会怎样？
3. `GPIOA->ODR` 的 bit5 置 1，对应哪个引脚？

## 3. 阶段 B（W3–W5）：让时间可控

### 第 3 周 · 定时器与中断

- [ ] TIM 配 1ms 中断，用它闪灯
- [ ] **手算一遍** PSC / ARR 与计数频率的关系
- [ ] 写非阻塞 `millis()`
- [ ] 用 `millis()` 实现"每 500ms 翻转 LED"，程序里不出现 `HAL_Delay`
- [ ] 中断里只置标志位，处理放主循环

### 第 4 周 · PWM 与舵机

- [ ] 配 TIM PWM 50Hz（PSC=71，ARR=19999）
- [ ] 用 CCR 控制脉宽 500~2500μs
- [ ] 舵机转到 0°/45°/90°/135°/180°，用量角器验证
- [ ] 记录实际角度与 CCR 的对应表（**你会发现它不是线性的**）
- [ ] 按键切换角度

### 第 5 周 · 加减速与标定

- [ ] 实现"平滑移动"（每 10ms 走 1°）
- [ ] 加梯形或 S 曲线加减速
- [ ] 做脉宽-角度标定表存进代码
- [ ] 软件限位（防止撞死）
- [ ] 串口打印当前角度

### 阶段 B 的 AI 对照练习

让 AI 给出 PSC/ARR 的计算过程和一段 PWM 初始化代码：

- 自己手算一遍再对比——**不一致时必须能说清谁对**
- 检查它有没有考虑：定时器时钟来源、重装载预装载、舵机死区

### 阶段 B 的仪器验证

- [ ] 逻辑分析仪抓 PWM：确认周期 20ms、高电平宽度对应 CCR
- [ ] 示波器看舵机信号线上的实际脉宽

**阶段 B 验收题**

1. 为什么 PSC=71、ARR=19999 就是 50Hz？
2. 舵机抖动，可能有哪些原因？（至少 3 个）
3. 非阻塞延时是怎么实现的？

## 9. 四个会让你原地踏步的坑

1. **教程循环**：看视频 → 抄代码 → 能跑 → 以为会了。  
   **破解**：关掉教程从零重写一遍。

2. **不会调试**：没有示波器、不会断点、只会 `printf` 和重启。  
   **破解**：阶段 A 就把调试器用熟，能省后面 30 天。

3. **贪多**：同时开 5 个外设，最后不知道错在哪。  
   **破解**：一次只加一个变量。

4. **AI 依赖**：让 AI 写完直接贴，能跑就过。  
   **破解**：每条 AI 生成的代码你必须能解释；每阶段至少一次仪器验证。  
   **代价**：不这样做的后果不是"慢"，是"出问题时你修不了"。

## 10. 卡住时的自查顺序

1. 电源对不对？（万用表量电压）
2. 地共了吗？
3. 引脚复用配了吗？（CubeMX 里看）
4. 时钟使能了吗？
5. 用逻辑分析仪看波形，别猜
6. 最后才怀疑代码逻辑
7. 还不行，把现象完整描述给 AI——**描述清楚现象本身就是能力**
