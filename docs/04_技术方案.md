## 1. 三级架构与时间契约

```
┌──────────────────────────────────────────────────────────────┐
│ L2 认知层（边缘算力：先用笔记本）                               │
│   · 视觉行为识别（在座/离开/看手机/低头/趴桌）                 │
│   · 记忆系统（事件摘要 + 遗忘曲线 + 人格 profile）             │
│   · 主动交互策略（打扰成本建模）                               │
│   · 时间尺度：100ms ~ 秒级，允许抖动                           │
└───────────────────────────┬──────────────────────────────────┘
                            │ WiFi / USB（异步、可丢、带时间戳）
┌───────────────────────────┴──────────────────────────────────┐
│ L1 感知层（ESP32-S3）                                          │
│   · I2S 麦克风 INMP441：VAD + 关键词唤醒                       │
│   · 毫米波雷达 LD2410：在场 / 静止 / 微动（隐私友好）          │
│   · 声学环境（噪声等级、是否有人在说话）                       │
│   · 时间尺度：10 ~ 300ms                                      │
└───────────────────────────┬──────────────────────────────────┘
                            │ UART（定长帧 + CRC + 优先级 + 心跳）
┌───────────────────────────┴──────────────────────────────────┐
│ L0 反射层（STM32F103C8T6）                                     │
│   · 1kHz 舵机控制环 + 电流采样 + 堵转/过流保护                 │
│   · 参数化表情渲染（SSD1306，局部刷新，≥35fps）                │
│   · 共享情绪状态槽（唯一真值源）+ 状态机                       │
│   · 时间尺度：微秒 ~ 10ms，硬实时、不可丢                      │
└──────────────────────────────────────────────────────────────┘
```

### 1.1 为什么必须分层

AI 推理延迟是**秒级且抖动**的，而"转头朝向用户"必须在 **150ms** 内完成。
如果把 AI 直接接在执行器上，症状是：表情抽风、转头一顿一顿、摸头没反应。

所以本项目采用 **慢脑 - 快反射（Slow-Brain / Fast-Reflex）**：

- **快反射**在 MCU 上，永远在线，不问 AI，保证"活着的感觉"；
- **慢脑**只在边缘侧做"建议"，**不允许直接控制执行器**，只能写"情绪状态槽"。

> 对应具身智能里的 dual-process / System 1 & 2 思路。
> **这是本项目最值钱的一句话。**

### 1.2 延迟预算

| 通路 | 预算 | 说明 |
|---|---|---|
| 触摸/电流 → 表情变化 | **< 50 ms** | 反射层直连，不经网络 |
| 人脸移动 → 舵机到位 | **< 150 ms** | 含视觉延迟补偿 |
| 说话 → 唤醒灯亮 | **< 300 ms** | 端侧唤醒词 |
| 状态变化 → 主动开口 | **< 2 s** | 慢脑决策 |
| 断网/断电 → 安全停止 | **< 100 ms** | 心跳超时保护 |

要求：每项都要实测并公开数据（**均值 + P95 + 抖动**）。

## 2. 五个创新点

### 2.1 慢脑 - 快反射 + 参数化表情空间

**问题**：现有桌面机器人要么表情是几张贴图硬切（廉价感），要么 AI 直接驱动表情（抖动）。

**做法**：
- 不用现成表情库（RoboEyes 之类），自写 **参数化矢量渲染**：
  眼睛开合度、瞳孔位置、眉毛倾角、嘴部曲率等 6~8 个连续参数，直绘 SSD1306。
- 定义 **4 维共享情绪状态槽**：`valence`（愉悦）、`arousal`（唤醒）、`attention`（注意）、`fatigue`（疲劳），范围 0~1。
- **唯一真值源**：表情参数、舵机姿态、语音语调、灯光全部从这 4 个数派生。
- 状态转移由 L0 自己走（快），L2 只能"建议目标状态"（慢），L0 用指数平滑过渡。

**为什么不是噱头**：它解决的是真实的工程矛盾——AI 的高延迟抖动 vs 交互的实时性要求。所有具身智能系统都要面对这个问题。

**验证**：四种输出的一致性；状态切换的视觉平滑度（帧间参数差）；**AI 断连时表情是否依然自然**。

### 2.2 无传感器力感知：把舵机电流变成触觉 ★ 优先做

**问题**：摸头互动普遍用 TTP223 触摸模块——加个传感器就完事，没有技术含量，且只能感知"摸到了"，感知不到"多大力"。

**做法**：
- 舵机电源回路串 **0.1Ω 采样电阻 + MCP6002 差分放大 33 倍**（低边采样）。
- STM32 ADC 在 PWM 周期内多点采样（10kHz），TIM 触发 + DMA 循环。
- 特征：均值、RMS、峰值、上升沿斜率、与指令位置的残差。
- 分类 4 类：**自由运动 / 被轻触 / 被人推动 / 堵转卡死**。先用决策树，跑通再考虑 CMSIS-NN。
- 由此实现三个功能：
  1. **触摸检测（带力度分级）**：轻拍 = 眯眼放松，重按 = 皱眉后撤
  2. **柔顺退让**：被推动时舵机主动让位（阻抗控制雏形）
  3. **堵转保护**：卡住 200ms 自动卸力，防烧舵机

**为什么前沿**：这叫 **sensorless force estimation（无传感器力估计）**，是协作机器人 / 机器狗里的正经方向。用一个 5 块钱的模拟电路 + MCU 自带 ADC 实现，**零额外传感器成本**。

**验证**：4 类分类准确率、力估计误差、误触发率、柔顺模式跟随误差。

**加分项**：后期换 **STS3215 总线舵机**（直接读负载/位置）做**对比实验**——"低成本无传感器 vs 总线舵机"。这个对比本身就是一篇小论文的骨架。

### 2.3 隐私优先的在场感知（不采集图像判断在场）

**问题**：专注监测类产品普遍以摄像头采集用户图像，隐私是主要落地障碍；桌面陪伴场景尤其敏感。

**做法**：
- **主通路（默认）**：毫米波雷达 LD2410（约 40 元）做在场/静止/微动检测，配合麦克风能量做"是否在学习 / 是否在说话"的粗判。**不采集任何图像。**
- **增强通路（可选）**：USB 摄像头 + 端侧小模型，只在本地推理，只输出**离散行为标签**，**不保存图像、不上传**。
- 关键设计：**做行为，不做情绪**。Ekman 六情绪在真实场景准确率很低，难以复现；"在座/离开/看手机/低头/趴桌"才是扎实的。

**为什么前沿**：把隐私当作**技术约束**而非合规口号，该约束会迫使架构选择更优路径（雷达 + 声学替代视觉）——这与智能家居 / 养老监护的技术路线一致。

**验证**：在场检测准确率 / 误报率；有遮挡、多人、背对场景的鲁棒性；**摄像头关闭时功能降级程度**。

---

### 2.4 遗忘曲线记忆系统（不是又一个向量库）

**问题**：几乎所有"有记忆的机器人"都是把聊天记录塞进向量库做 RAG。结果**记得一切 = 什么都不重要**。

**做法**：
- 记忆条目带 **强度（strength）** 和 **最后访问时间**：
  - 每次被提及 → 强度上升
  - 随时间按艾宾浩斯曲线衰减
  - 低于阈值 → 归档；高于阈值 → 进入"该主动回忆"候选池
- 记忆分三层：**事实记忆**（专业、作息）、**事件记忆**（上周三熬夜了）、**偏好记忆**（讨厌被叫早）。
- 派生一个**可解释的人格 profile**：用词、语气、主动程度随交互缓慢漂移，但所有参数可查、可重置。

**为什么前沿**：这是**认知架构**层面的思考，不是检索层面。实现成本低（本地 SQLite + 打分函数），不需要大算力。

**验证**：跨会话回忆正确率；7 天 / 30 天后重要记忆保持率；"主动回忆"的恰当率。

---

### 2.5 打扰成本建模的主动交互

**问题**：现有桌面机器人多为被动响应式，仅在用户唤起后动作。主动发起是陪伴类产品的核心能力，但误触发开口的代价高于不开口。

**做法**：
- 输入：在场状态、连续学习时长、看手机次数、当前时间、环境噪声、历史响应率
- 输出：{沉默 · 微表情 · 动作+表情 · 语音}，四级强度
- **核心机制：打扰成本（interruption cost）在线学习。**
  每次主动干预后记录用户反应（理了 / 没理 / 明确拒绝），用多臂老虎机或简单策略梯度在线调整触发阈值。
- **安全约束（硬编码，AI 不可覆盖）**：静音时段、单次会话干预上限、用户拒绝后 30 分钟冷却。

**为什么前沿**：这是 **human-in-the-loop 的策略学习**，把推荐系统里的"打扰模型"落到了物理世界。而且可测量。

**验证**：干预接受率（是否被理睬）；随时间是否上升；对比固定规则基线做 A/B。

## 3. 关键参数（可直接写代码）

| 项 | 值 | 备注 |
|---|---|---|
| 舵机 PWM | 50Hz，500~2500μs，1μs 分辨率 | 72MHz，PSC=71，ARR=19999 |
| 电流采样 | 0.1Ω 低边 + 33 倍差分，双通道 | 700mA → 2.3V；约 0.24mA/LSB |
| 采样率 | 10kHz 连续；每 20ms（一个 PWM 周期）处理 **200 点** | TIM 触发 ADC + DMA 双缓冲 |
| 表情刷新 | **只刷脏矩形**，目标 ≥35fps | I2C 400kHz 全屏 1KB 理论只到 ~43fps，全屏刷必掉帧 |
| 情绪状态 | 4 维 float，100Hz 更新，指数平滑 τ=0.3s | L0 拥有，L2 只能写目标值 |
| 计时精度 | DWT 周期计数器（72MHz，13.9ns） | 延迟测量全靠它 |

## 4. 通信协议（UART 115200 8N1）

### 4.1 帧格式

```
0xAA 0x55 | type(1) | seq(1) | len(1) | payload(0~32) | crc8(poly 0x07)
```

### 4.2 消息类型

| type | 名称 | 方向 | 优先级 |
|---|---|---|---|
| 0x01 | 心跳 | 双向 | 高 |
| 0x02 | 情绪目标 | L2 → L0 | 中 |
| 0x03 | 表情/动作指令 | L1 → L0 | **高** |
| 0x04 | 触摸/力事件 | L0 → L1 | **高** |
| 0x05 | 状态上报 | L0 → L1 | 低 |
| 0x06 | 安全 / 急停 | 任意 → L0 | **最高** |
| 0x07 | 日志 | 任意 | 最低 |

### 4.3 约束

- 优先级：安全 > 表情/力事件 > 情绪目标 > 状态上报 > 日志
- 心跳 **100ms**，超时 **300ms** → 舵机卸力、表情进入"独立模式"
- 时钟同步：用往返时延估计做偏移补偿，跨板延迟才测得准

## 5. 反噱头清单

| 不做 | 原因 |
|---|---|
| 接 GPT API 做通用对话 | 无技术含量，断网即不可用，且已属常见实现，无法形成差异化 |
| 情绪识别（判断用户情绪状态） | 学术上不可靠，真实场景准确率低 |
| 堆砌十几种传感器 | 每个都只是"能读到数"，没有闭环 |
| 花哨外壳掩盖空洞内核 | 顺序错了：先做闭环，再做好看 |
| 追求"机器人产生意识" | 无法验证，也无法形成可复现的结论 |

## 6. 选型理由

| 选择 | 理由 |
|---|---|
| STM32F103 而非直接上 ESP32 | 已经在学，外设基础通用；F103 负责硬实时，职责清晰 |
| ESP32-S3 而非树莓派 Pico | 自带 WiFi/BLE + I2S + PSRAM，能跑端侧唤醒词 |
| 边缘算力先用笔记本 | 唯一可能白买的部件，P3 确认需要再买 |
| MCP6002 而非 LM358 | 轨到轨输出，33 倍增益下带宽够，电机电流纹理不失真 |
| 雷达而非摄像头做主通路 | 隐私友好，且逼出更好的架构；摄像头只做可选增强 |
| 参数化渲染而非 RoboEyes | 连续情绪可插值，且避免"教程味" |
